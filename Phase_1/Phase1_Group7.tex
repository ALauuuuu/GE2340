\section{Problem Definition \& Scope}
Currently, the campus dining resources are fragmented and unevenly digitized, with several canteens continuing to utilize physical menus and lacking a platform that allows for real-time access to campus dining menus. Moreover, the campus community encompasses diverse economic, cultural, and religious backgrounds. When choosing meals, students and staff weigh multiple factors based on their needs, such as budget, distance to the canteen, cuisine style, dietary preferences, religious restrictions, and food allergies, which poses a decision-making challenge. When facing these complex personal considerations, traditional manual searching is time-consuming and inefficient, often leading to unnecessary expenditure of effort. To address this problem, this project aims to introduce an artificial intelligence approach to build an efficient meal recommendation system.

The scope of this project includes a hybrid recommendation chatbot that uses an LLM to process natural language, extract the user intent, and perform data enrichment. It integrates this language processing with a rule-based scoring backend using structured menu databases to provide explainable recommendations.
The scope excludes restaurant foot traffic tracking or training a customized LLM from scratch.

\section{AI Task Formulation}
This project is formulated as a context-aware conversational recommendation task in which the system receives a natural-language query from the user and returns a ranked list of recommended canteen dishes with explanations. 

The collectible inputs include the locations, opening hours, and menus of campus canteens and restaurants, where dishes are labeled with ingredients, potential allergens, prices, whether they are cold or hot, and the dish name. Emotion/intent examples, such as sadness, coldness, and stress, along with their corresponding food types, may also be collected. For instance, a user expressing sadness might be recommended comfort foods labeled as sweet.

The expected outputs are a table containing a ranked list of the top k recommended dishes, unless specified otherwise, with a natural-language explanation for each recommendation, and the details of the recommended dishes. The unit of prediction/decision is a table of ranked recommendations and corresponding details per user query. 

Constraints are that recommendations must be limited to currently available menu items and must not ignore or violate allergies, religious or dietary restrictions, budget, or canteen hours. User satisfaction will be measured via a satisfaction survey after each interaction, asking users to rate the relevance and usefulness of the recommendations on a 1-5 scale. Responses will then be used for calculating an overall mean satisfaction score. Success is defined as achieving a mean score of at least 3.5/5.0.

Data sources include canteen and restaurant locations, opening hours, and menus obtained via official websites or APIs; public weather APIs; surveys on user preferences; and user queries and feedback collected through the chatbot interface. Privacy, consent, and access considerations include obtaining authorization to access menu data, complying with API terms, collecting anonymized user data with opt-in consent, allowing deletion, and complying with institutional and applicable regulations.
